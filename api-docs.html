1. Introducción

La API de pronóstico de B1TMET entrega pronósticos numéricos del modelo WRF de alta resolución para el Caribe y Centroamérica, en JSON. Se usa con cualquier lenguaje, desde un servidor o desde el navegador.

  • URL base: https://thredds.b1tmet.com/v1
  • Formato: JSON en UTF-8. Solo peticiones GET.
  • Tiempos: ISO 8601 en UTC (2026-10-31T03:00:00Z).
  • Valores ausentes: null, nunca 0.
  • Pronóstico: pasos cada 3 h, hasta 72 h. El modelo se ejecuta 4 veces al día (00, 06, 12 y 18 UTC).

Planes y precios: Precios de la API. Condiciones de uso: Términos de la API.

2. Inicio rápido

  1. Solicita una clave desde la página de precios. Recibirás una clave con el formato b1t_live_….
  2. Haz tu primera petición: pronóstico de 24 horas para La Habana.
curl "https://thredds.b1tmet.com/v1/forecast/point?lat=23.13&lon=-82.38&hours=24" \
  -H "Authorization: Bearer b1t_live_TU_CLAVE"
const res = await fetch(
  "https://thredds.b1tmet.com/v1/forecast/point?lat=23.13&lon=-82.38&hours=24",
  { headers: { Authorization: "Bearer b1t_live_TU_CLAVE" } }
);
if (!res.ok) {
  const { error } = await res.json();
  throw new Error(`${res.status} ${error.code}`);
}
const forecast = await res.json();
console.log(forecast.data[0].temperature_2m);
import requests

r = requests.get(
    "https://thredds.b1tmet.com/v1/forecast/point",
    params={"lat": 23.13, "lon": -82.38, "hours": 24},
    headers={"Authorization": "Bearer b1t_live_TU_CLAVE"},
    timeout=60,
)
r.raise_for_status()
forecast = r.json()
print(forecast["data"][0]["temperature_2m"])

Una petición que no está en caché tarda unos segundos (el pronóstico se calcula en ese momento). Las siguientes para el mismo punto se responden en milisegundos. Usa un timeout de 60 s.

3. Autenticación

Envía la clave en la cabecera Authorization (recomendado) o como parámetro apikey:

Authorization: Bearer b1t_live_TU_CLAVE
https://thredds.b1tmet.com/v1/usage?apikey=b1t_live_TU_CLAVE
  • Si envías las dos, se usa la cabecera.
  • La API admite peticiones desde cualquier origen (CORS), así que puedes llamarla desde el navegador.
  • Una clave incluida en una web es visible para cualquiera. Si sospechas que se ha filtrado, escríbenos: la revocamos y te damos otra.
  • Las claves del plan Free caducan a los 30 días y se pueden renovar.

6. Selección de dominio

Con domain=auto, la API usa el grid más detallado de tu plan que cubre el punto y, entre dominios equivalentes, el más centrado respecto al punto. Si el preferido no tiene datos en ese momento, usa el siguiente.

La respuesta indica siempre en model el dominio y el grid usados. Si necesitas resultados reproducibles, fija domain y grid.

9. Buenas prácticas

  • Cachea en tu lado hasta lo que indica Cache-Control. El pronóstico de un punto no cambia hasta la siguiente actualización.
  • Usa siempre las mismas coordenadas para el mismo lugar (por ejemplo, con 4 decimales fijos): así tus peticiones se sirven desde caché y responden más rápido.
  • Respeta Retry-After en los 429 y 503, y reintenta con espera creciente.
  • Timeout de 60 s en el cliente: una petición sin caché tarda unos segundos.
  • Ignora los campos que no conozcas: dentro de v1 pueden añadirse campos nuevos.
  • Protege tu clave: en producción, llama a la API desde tu servidor siempre que puedas.
  • Atribución: en los planes Free y Starter, muestra «Pronóstico: B1TMET» junto a los datos publicados (ver Términos de la API).

10. Versiones y cambios

La versión v1 es estable: solo recibe cambios compatibles (campos, variables, parámetros opcionales o endpoints nuevos). Los cambios incompatibles se publicarán en /v2, y /v1 se mantendrá al menos 12 meses desde el anuncio, con las cabeceras Deprecation y Sunset.

1. Introduction

The B1TMET forecast API delivers high-resolution WRF numerical forecasts for the Caribbean and Central America, in JSON. Use it from any language, from a server or from the browser.

  • Base URL: https://thredds.b1tmet.com/v1
  • Format: UTF-8 JSON. GET requests only.
  • Times: ISO 8601 in UTC (2026-10-31T03:00:00Z).
  • Missing values: null, never 0.
  • Forecast: 3-hour steps, up to 72 h. The model runs 4 times a day (00, 06, 12 and 18 UTC).

Plans and pricing: API Pricing. Terms of use: API Terms.

2. Quick start

  1. Request a key from the pricing page. You will receive a key in the format b1t_live_….
  2. Make your first request: a 24-hour forecast for Havana.

  -H "Authorization: Bearer b1t_live_YOUR_KEY"

  "https://thredds.b1tmet.com/v1/forecast/point?lat=23.13&lon=-82.38&hours=24",

console.log(forecast.data[0].temperature_2m);
import requests

r = requests.get(

A request that is not cached takes a few seconds (the forecast is computed on the fly). Later requests for the same point are answered in milliseconds. Use a 60-second timeout.

3. Authentication

Send the key in the Authorization header (recommended) or as the apikey parameter:

Authorization: Bearer b1t_live_YOUR_KEY
https://thredds.b1tmet.com/v1/usage?apikey=b1t_live_YOUR_KEY
  • If you send both, the header is used.
  • The API accepts requests from any origin (CORS), so you can call it from the browser.
  • A key embedded in a website is visible to anyone. If you think it has leaked, contact us: we will revoke it and issue a new one.
  • Free plan keys expire after 30 days and can be renewed.

6. Domain selection

With domain=auto, the API uses the most detailed grid in your plan that covers the point and, among equivalent domains, the one best centered on the point. If the preferred one has no data at that moment, it uses the next one.

The response always shows the domain and grid used in model. If you need reproducible results, set domain and grid.

Each plan has a per-minute and a daily request limit, a maximum horizon and a set of grids. The values are on the API Pricing page. Quotas are per customer and shared by all of the customer's keys.

9. Best practices

  • Cache on your side for as long as Cache-Control allows. A point's forecast does not change until the next update.
  • Always use the same coordinates for the same place (for example, with 4 fixed decimals): your requests will then be served from cache and answered faster.
  • Respect Retry-After on 429 and 503, and retry with increasing waits.
  • Use a 60-second timeout in your client: an uncached request takes a few seconds.
  • Ignore fields you don't know: new fields may be added within v1.
  • Protect your key: in production, call the API from your server whenever possible.
  • Attribution: on the Free and Starter plans, show "Forecast: B1TMET" next to published data (see the API Terms).

Version v1 is stable: it only receives compatible changes (new fields, variables, optional parameters or endpoints). Incompatible changes will be released as /v2, and /v1 will be kept for at least 12 months from the announcement, with the Deprecation and Sunset headers.
